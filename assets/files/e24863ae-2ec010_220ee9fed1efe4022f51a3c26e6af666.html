04 How it works, technically

The decisions below are what make it survive in production. Everything else is plumbing.

Material & texture resolution by convention

No hardcoded references. It leans on the artists' render-folder structure, their strict asset naming (each character's textures live in its own texture/ folder, named SKIN_00/_01/_02 etc.), and a fixed Blender object hierarchy where the same names always live in the same place. A mesh resolves to the right shader because the convention says so not because a script memorised it.

Fail loud, keep rendering

Nothing is allowed to fail silently. If no rule matches, an obvious placeholder material is substituted so the broken asset is identifiable at a glance, and every unresolved object is written to a log.txt. Blender always exports something worst case an empty, transparent result so a bad or mis-exported asset is visible in seconds.

Deterministic by design

Same input, same output, every time see "regenerate, don't patch" below. Fixed render settings, fixed rules, no hidden state, no drift between two runs.

Headless and portable

Blender runs in --background mode driven by bpy. It runs on any PC on the network with Blender installed, so no single artist becomes the bottleneck.

# resolve_materials.py shader assignment from folder + naming (excerpt)
import bpy, os, logging
log = logging.getLogger("render_pipeline")

# Convention: one material slot per mesh. Multi-material objects are
# never half-applied each mesh gets exactly one shader, fully.
TEXTURE_RULES = {
    "SKIN":  "mat_skin",
    "METAL": "mat_metal",
    "CLOTH": "mat_cloth",
}

def resolve_material(obj, tex_dir):
    if obj.type != "MESH":
        return

    for token, mat_name in TEXTURE_RULES.items():
        # Textures live in the character's texture/ folder,
        # named like SKIN_00, SKIN_01, METAL_00, ...
        if any(t.upper().startswith(token) for t in os.listdir(tex_dir)):
            obj.data.materials.clear()
            obj.data.materials.append(bpy.data.materials[mat_name])
            return

    # No match → obvious placeholder + log the unresolved object
    obj.data.materials.clear()
    obj.data.materials.append(bpy.data.materials["mat_PLACEHOLDER"])
    log.warning(f"Unresolved object: {obj.name} (no matching texture in {tex_dir})")

05 Why it's stable regenerate, don't patch

My first version tried to update hand-built shaders with hardcoded values. It worked until it didn't. Too fragile and unpredictable.

The fix was to stop patching and start regenerating: every batch rebuilds the shaders from zero. No accumulated state, no half-applied edits, no drift between runs. Same input, same result, every time deterministic by design.
